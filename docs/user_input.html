Introduction

This page details how Bookbinder JS captures and processes user interactions. Understanding this flow is key to understanding how user choices are translated into the final PDF output.

The Form (index.html & HTML Partials)

The main user interface for Bookbinder JS is a large HTML form defined in the root index.html file. This form contains all the input fields, dropdowns, and buttons that users interact with to configure their bookbinding layout.

To keep the main index.html manageable and promote reusability, the form is constructed by including various HTML partials from the src/html/ directory. These partials represent different sections of the UI, like paper options, layout settings, etc. A custom script handles directives like the one below to load these partials:

<!-- Example: How a partial might be indicated in index.html -->
<load src="src/html/file.html" />

(Note: The actual mechanism for including partials is handled by the vite-plugin-html-inject during the build process, configured in vite.config.js, which processes special <load> tags.)

Event Listeners (src/main.js)

The JavaScript execution for the application starts in src/main.js. After the HTML document is fully loaded (DOMContentLoaded event), this script attaches event listeners to various form elements. These listeners wait for user actions, such as changing an input value, selecting a file, or clicking a button.

Here's a simplified example of how event listeners are set up:

View code example: Event listener setup in src/main.js 
// Simplified example from src/main.js
// Wait for the DOM to be fully loaded
document.addEventListener('DOMContentLoaded', () => {
    const book = new Booklet(); // Central object holding book data
    const bookbinderForm = document.getElementById('bookbinder_form'); // The main form

    // Listener for the file input
    const fileInput = document.getElementById('input_file');
    if (fileInput) {
        fileInput.addEventListener('change', (e) => {
            handleFileChange(e, book, bookbinderForm); // Process the selected file
        });
    }

    // Listeners for other inputs (text, select, radio, etc.)
    const inputs = bookbinderForm.querySelectorAll('input:not([type="file"]), select');
    inputs.forEach((input) => {
        input.addEventListener('change', () => {
            handleInputChange(book, bookbinderForm); // Handle general input changes
        });
    });

    // ... other listeners for buttons etc. ...
});

Handling Input Changes (src/utils/changeHandlers.js)

User interactions that modify form values are primarily handled by functions in src/utils/changeHandlers.js.

handleInputChange(book, bookbinderForm)

This function is typically called when the value of most form inputs (text fields, dropdowns, checkboxes, etc.) changes. Its main responsibilities are:

  • Gathering all current form data using new FormData(bookbinderForm).
  • Calling saveForm(formData) (from src/utils/formUtils.js) to persist the current settings, likely to the browser's local storage.
  • Updating the central book object with the new configuration values. This object holds the state of the document to be processed.
  • Triggering UI updates, such as re-rendering parts of the form or previews, by calling functions like updateRenderedForm(bookbinderForm, book).
View code example: Simplified handleInputChange 
// Simplified concept of handleInputChange
async function handleInputChange(book, formElement) {
    const formData = new FormData(formElement);
    saveForm(formData); // Persist data

    // Update the book object with new values from formData
    book.setOptionsFromFormData(formData); // Links to book object above

    // Reflect changes in the UI
    updateRenderedForm(formElement, book); // Links to updateRenderedForm above

    // Potentially re-render a preview if a PDF is loaded
    if (book.pdfDoc) {
        // ... logic to re-render preview ...
    }
}

handleFileChange(event, book, bookbinderForm)

This function is specifically triggered when a user selects a PDF file using the file input field (<input type="file" id="input_file">). Its key actions include:

  • Retrieving the selected file from the event object.
  • Calling book.openpdf(file). This asynchronous method in the Booklet class (likely defined in src/booklet.js) is responsible for reading and processing the PDF file using PDF-Lib.
  • After the PDF is processed, it also triggers UI updates, similar to handleInputChange, to reflect that a file is loaded and its properties (like page count) are known.
View code example: Simplified handleFileChange 
// Simplified concept of handleFileChange
async function handleFileChange(event, book, formElement) {
    const file = event.target.files[0];
    if (file) {
        try {
            await book.openpdf(file); // Process the PDF
            // Update UI based on the loaded PDF
            handleInputChange(book, formElement); // Refresh form state and UI
        } catch (error) {
            console.error("Error opening PDF:", error);
            // Display error to user
        }
    }
}

Managing Form Data (src/utils/formUtils.js)

The src/utils/formUtils.js file contains utilities for managing the form's data persistence. This helps users retain their settings across browser sessions.

  • saveForm(formData): This function takes the current FormData object and saves it. It likely iterates over the form data and stores it in the browser's localStorage or sessionStorage.
  • loadForm(formElement, book): When the application first loads, this function is called to retrieve any previously saved form data from browser storage. It then populates the form fields with these saved values and updates the central book object accordingly.

These utilities ensure that if a user customizes their settings, closes the browser, and then reopens the application, their previous configuration is restored, providing a more user-friendly experience.
