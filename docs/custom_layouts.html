Introduction

This page focuses on how page layouts (the arrangement of individual pages onto larger sheets for printing) are defined and rendered within Bookbinder JS. It also provides guidance on which parts of the code would need modification if you wanted to implement custom layout schemes, such as different ways pages are embedded or arranged on a signature.

UI Representation of Layout (src/html/page_layout.html)

The user interface elements that allow users to choose and configure page layouts are likely defined in an HTML partial, such as src/html/page_layout.html (the exact filename might vary, e.g., layout_options.html). This file would contain the form inputs (dropdowns, radio buttons, number fields for margins, etc.) that users interact with to select their desired imposition style (e.g., booklet, N-up), paper orientation, margins, and other layout-specific settings.

Modifications to this HTML file would primarily change the user-facing options. For example, to introduce a new custom layout, you might add a new option to a dropdown menu here. While these changes don't alter the core layout logic directly, they provide the necessary user input that your custom layout functions would then use.

Core Layout Logic (src/booklet.js and src/utils/layout.js)

As mentioned previously, the Booklet class (from src/booklet.js) and its createoutputfiles() method are central to generating the final arrangement of pages. This method orchestrates the process of taking user inputs and the source PDF to produce the imposed output.

The actual calculations for determining where each page from the source PDF is placed on the output sheets (signatures) are performed by functions within src/utils/layout.js. This file contains the specific algorithms for different layout types (e.g., booklet, 2-up, 4-up, etc.). These functions would calculate the precise X/Y coordinates, rotation, and scaling for each page based on the selected layout options and the Booklet object's configuration (paper size, margins, source PDF page size, etc.).

The createoutputfiles() method in src/booklet.js would then call the appropriate functions from src/utils/layout.js based on the user's selected layout type and use the returned information to draw the pages onto the new PDF document using a library like PDF-Lib.

Guidance for Customization

Adding a new custom page layout is an advanced modification. Here's a general approach:

  1. Define UI Elements: If your new layout requires specific user-configurable options, add the necessary form elements to the relevant HTML partial (e.g., src/html/page_layout.html).
  2. Handle New UI Inputs: Update src/main.js to correctly read and process any new UI elements. Ensure these new options are passed to or stored in the Book object so the layout functions can access them. This typically involves updating handleInputChange or similar functions.
  3. Implement Core Layout Logic:
    • In src/utils/layout.js, create new functions or extend existing ones to perform the calculations for your custom layout. These functions will need to determine the position, rotation, and possibly scaling for each page of the source PDF onto the output sheets.
    • This logic will depend heavily on the specifics of your custom layout (e.g., how many pages per sheet, their order, orientation, any specific folding patterns).
  4. Integrate into PDF Generation:
    • Modify the createoutputfiles() method in src/booklet.js (or functions it calls). Add conditional logic to check if your new custom layout type has been selected.
    • If selected, ensure it calls your new layout calculation functions from src/utils/layout.js and uses the returned data to draw the pages accordingly.

Important: This process requires a good understanding of the existing layout calculations, how PDF coordinates work, and the capabilities of the PDF generation library (PDF-Lib) being used. Thorough testing with various PDF inputs and settings is crucial.

// Conceptual: How a new layout function might be added to src/utils/layout.js
function calculateMyCustomLayout(bookConfig, sourcePageNum, totalSourcePages) {
    // bookConfig contains all settings: paper size, margins, custom options...
    // sourcePageNum is the current page from the input PDF being placed.

    let x = 0, y = 0, rotation = 0, scale = 1;
    // Example: A simple 2-up side-by-side, centered
    const sheetWidth = bookConfig.paperWidth;
    const sheetHeight = bookConfig.paperHeight;
    const contentWidth = bookConfig.sourcePageWidth * 2; // Assuming two pages fit

    if (sourcePageNum % 2 === 1) { // First page of a pair
        x = (sheetWidth - contentWidth) / 2;
    } else { // Second page of a pair
        x = (sheetWidth - contentWidth) / 2 + bookConfig.sourcePageWidth;
    }
    y = (sheetHeight - bookConfig.sourcePageHeight) / 2;

    return { x, y, rotation, scale, sheetNumber: Math.floor((sourcePageNum -1) / 2) };
}
